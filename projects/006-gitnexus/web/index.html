    06 / THREE TOOLS, DIFFERENT EMPHASES
    同一条路线，
    三种使用重心。
    CodeFlow 偏快速浏览与报告；Ix 偏持久结构维护；
    GitNexus 偏围绕开发任务返回上下文。
    它们共享多项能力，选型取决于具体任务。
    
      
    三种重心 ↓核心矩阵 ↓相对优势 ↓任务演示 ↓
    
      
    解析源码→提取并连接关系→查询或计算→交给人或 AI
    差别集中在关系粒度、保存与更新、结果组织和使用入口。
    
      
    
        
    01任务查询
    GitNexus
    围绕一个符号，组织开发上下文。
    符号 · 关系 · 候选流程↓本地 LadybugDB↓CLI / MCP / HTTP / 网页
    • 查询调用上下文、潜在影响和入口路径
    • 把分组、流程参与信息纳入结果
    • 嵌入式索引，单机运行组件较少
    适合 给编程助手提供局部上下文，调查公共函数修改。
    核对架构与工具 ↗
    
        
    02结构维护
    Ix
    维护可持续查询、追溯的结构图。
    符号 · 调用 · 导入 · 图谱修订↓ArangoDB + memory-layer↓Docker 后端 → CLI / MCP / Compass
    • map / watch 持续维护代码结构
    • history / diff 追踪图谱实体和修订
    • 结构导航、子系统分析与有限上下文
    适合 长期跟踪仓库结构，查询依赖及结构变化。
    核对架构与命令 ↗
    
        
    03快速浏览
    CodeFlow
    把仓库结构变成可浏览的视图。
    函数信息 · 文件关联 · 目录指标↓浏览器分析 + 摘要 / 导出↓交互视图 / 源码卡片 / 报告
    • 无需业务后端，可直接打开本地文件
    • 浏览关系、目录、规模和源码卡片
    • 多格式导出与 Card 指标记录
    适合 快速熟悉项目，做结构讲解与轻量报告。

    更新与检查analyze 更新；detect_changes 分析 Git diffmap / watch；history / diff 查询图谱修订CLI 监听；Card 保存指标历史
    
        
    运行组成本地嵌入式数据库，无需独立数据库服务Docker 中运行 ArangoDB 与 memory-layer浏览器运行；CLI 可提供本地网页
    
        
    研究底层实现解析、持久化、查询和展示可继续追源码公开 CLI 与解析；Scala 后端源码私有可沿解析与图形代码研究浏览器呈现
    
        
    使用时的取舍要维护索引，原生依赖与搜索扩展可能需处理要管理后端服务；镜像可用，后端源码不公开浏览器内存、采样和解析规则影响覆盖
    
      
    
      
    图谱修订不等于 Git commit，指标历史也不等于版本化代码图谱。Ix 命令参考 ↗Ix 后端边界 ↗
    

      
    相对 CodeFlow
    更适合把具体调查交给 Agent。
    以函数为目标，返回调用者、流程和分层影响；MCP 直接提供任务工具。CodeFlow 的强项是让人快速浏览文件结构与报告，也能导出 JSON 供后续处理。
    相对 Ix
    运行组件更少，底层链路更便于研究。
    GitNexus 使用嵌入式图数据库，可继续阅读建图、存储与查询实现。Ix 需要独立后端，后端镜像公开可用，Scala memory-layer 的源码位于私有仓库。
    
      
    能力交集也要看清。
    持久图谱、调用导航、影响分析、MCP、Agent 技能和 hooks 在 GitNexus 与 Ix 中都有对应能力。这里比较的是组织方式和运行取舍，尚无同仓库实验证明谁解析更准、速度更快或更省 Token。
