## 我们最终的理解

Pulse 是 macOS 原生的账号额度监控与本地用量分析应用。本研究关心的价值是后者：读取多个 Agent 已经保存或导出的调用记录，将模型标识与服务端 usage 计数整理成可核对的本地账本。账号额度与逐模型消耗是两条数据通道，不能混为一谈。

它通常从会话 JSONL、SQLite、任务 JSON、OTEL 或用量导出中取数。配置文件帮助定位记录或获取登录信息，钩子和接口按场景补充；单看配置中的默认模型，不能得知每次调用消耗。模型身份由客户端记录提供，不能独立证明服务器的真实路由。

## 能力、原理与价值

| 问题 | 结论 |
| --- | --- |
| 能力是什么？ | 按 Agent、模型、项目和日期统计输入、输出、缓存 Token，并按模型价格估算 API 等价费用；原应用另有额度、重置时间、多账号和提醒能力。 |
| 支持哪些来源？ | 目录识别 54 类来源，7 个原有读取器经过实机记录验证；47 个新增适配的验证程度不同，其中 6 类依赖预先导出或捕获。 |
| 如何识别模型？ | 读取消息的 model 字段，或将后续 usage 增量归给当前模型事件。 |
| 如何避免算错？ | 按消息 / 请求 ID 去重；累计值差分；排除分叉重放；依产品口径处理输入与缓存、输出与推理的重叠。 |
| 如何计算金额？ | 先按原始模型 ID 与 Token 类型查价，处理别名和适用价格层，再汇总。没有价格或分类时保留未定价。 |
| 对我的价值？ | 可以参考来源适配、标准记录、计数校正、价格匹配与聚合接口，独立实现类似的本地统计模块。 |

## 统计边界

Crush、Warp 只有成本或请求信息，Freebuff 没有可报告的真实 Token 计数；Cursor 等导出来源没有导出就没有数据。部分来源只有会话级时间或不完整分类。API 等价金额不等于订阅实付，不同设备、账号或缺失记录也不会自动补齐。

网页中的两模型记账示例使用明确标记的合成数据，只演示差分与去重；本页不扫描访问者的文件、不调用模型生成接口。
