# 对我的价值与扩展方向

## 可参考实现自己的统计模块

这份研究最值得复用的是格式适配和记账语义：把不同 Agent 的调用记录转换为同一模型，并把累积、缓存、重放与不完整数据处理正确。图形界面可以独立选择，统计模块也可接命令行、网页看板或自己的应用。

建议的产品结构是 `SourceAdapter → NormalizedUsageRecord → UsageAccumulator → PriceCatalog → QueryService`。这是基于研究提出的模块划分，不是声称上游已有同名跨平台 SDK。

## 分阶段实现（尚未实现）

| 阶段 | 目标 | 完成标准 |
| --- | --- | --- |
| 首版 | Codex + Claude Code，本地手动扫描 | 同一份样本反复扫描不重复计数；单模型、跨模型、缓存和 fork 样本能核对；缺失项明确显示。 |
| 增量采集 | 文件偏移、指纹缓存、SQLite 水位 | 追加、截断、日志轮换、恢复、归档后能与全量重算对齐。 |
| 来源扩展 | 根据实际工具逐个新增 Adapter | 每个来源记录路径、版本、单位、身份键和覆盖边界；保留真实脱敏样本。 |
| 产品界面 | 按模型、项目、Agent、时间查询 | 计数、估价、来源完整性可追溯，导出结果可重算。 |

## 可以扩展的方向

- **Windows / WSL**：分开解析原生与发行版路径、命令调用和配置覆盖；用记录身份排除镜像，不把跨平台目录差异等同于只改路径。
- **账户归因**：保留来源真正提供的账号 / 组织 ID；没有账号字段的记录标为未知，不根据当前登录推测历史归属。
- **价格快照与真实账单**：保存使用时价格版本、币种与适用条件；将 API 等价估算与服务商实际金额分栏，允许导入账单对账。
- **本地性能**：增量扫描、取消支持、低资源占用、错误隔离；损坏与未读文件计入覆盖说明。
- **模型与项目分析**：模型、工具和项目对比，缓存命中与趋势；不能仅凭本地 model 标签宣称识别了服务端真实路由。
- **预算与团队汇总**：预算预警和可选的脱敏汇总。团队同步、权限、服务端和保留策略均属于新产品设计，不是这份静态研究页已经实现的功能。

## 范围选择

优先实现自己日常使用的 Agent，先把 Token 数算准，再加入费用与趋势。54 类目录适合作为适配清单参考，不能直接作为“已兼容全部客户端”的产品承诺。
