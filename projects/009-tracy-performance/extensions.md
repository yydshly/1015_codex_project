# 扩展方向与 AI 时代价值

以下为产品设想，不代表 Tracy 内置能力，也不是本网页已部署的服务。

## 能否扩展成自动质量检测的库

可以。最直接的范围是自动性能回归 SDK / CLI：复用 Tracy 的采集与定位，在外层增加构建和场景执行、指标归一、基线比较、规则判定、报告和 CI 接口。更完整的质量检测还需要独立的正确性、静态及运行时检查。这里是设计评估，本项目没有交付或执行可用的质量检测 SDK。

建议形成一套“项目合同”：构建命令、固定输入/操作、预期业务结果、测量环境、重复次数、基线、预算和失败规则。Tracy 负责证据，规则层对已覆盖操作作判定；缺少数据或噪声过大时返回 INCONCLUSIVE，避免把没有结论当成通过。

~~~text
项目合同 → 构建/运行 → 正常基准 + 独立正确性测试
  → 按需 Tracy/平台采集 → 基线比较/判定 → JSON + trace + 热点/源码链接
  → CI 门禁 → 可选 AI 候选 → 重走同一套验收
~~~

建议接口分为 build / run / collect、compare / evaluate、report；这是封装层的接口草案，不是现有 Tracy API。产物应保存提交、环境、输入、业务结果、样本与原始采集记录，并返回 PASS / FAIL / INCONCLUSIVE。

| 质量维度 | Tracy 的贡献 | 外部能力 |
| --- | --- | --- |
| 耗时、卡顿与资源回归 | 区间、帧、调用路径、线程/锁、GPU 与已报告分配 | 代表性负载、正常基准、预算/统计规则和 CI；深度 profiling 与正常基准分开 |
| 功能和业务正确性 | 执行上下文帮助排查 | 断言与单元/集成/端到端测试；[CTest](https://cmake.org/cmake/help/latest/manual/ctest.1.html) 可编排 CMake 工程测试，预期结果由业务定义 |
| 内存安全 | 分配来源、存活与可选调用栈 | [AddressSanitizer](https://clang.llvm.org/docs/AddressSanitizer.html) 等检查越界/UAF；不能用分配曲线代替安全检查 |
| 数据竞争 | 线程和已接入锁的关系 | [ThreadSanitizer](https://clang.llvm.org/docs/ThreadSanitizer.html) 等运行时竞争检测，按构建与平台配置 |
| 静态代码质量与安全 | 热点可用于确定检查重点 | [clang-tidy](https://clang.llvm.org/extra/clang-tidy/) 等静态诊断，安全和依赖风险另用针对性检查 |
| 服务与 AI 产品体验 | 可控进程内部的执行证据 | 压测、浏览器、跨服务/数据库证据、TTFT 与生成速率等业务测量 |

对 AI 生成的普通软件和含 AI 的产品都具有价值：为代码生成之后提供独立反馈，减少排查与复测成本。自动判定的可信度受已覆盖需求、负载、平台和环境约束，不能推导为所有代码、所有输入都得到质量保证。

## 三个对象

| 对象 | 例子 | 指标 |
| --- | --- | --- |
| AI 生成的普通软件 | C++ 文件工具、CAD、网站、后端 | 耗时、内存、交互、并发、I/O、等待 |
| 包含 AI 的产品 | 推理服务、聊天应用、GPU 算子 | 通用指标，加首 Token、生成速率、显存、模型与服务等待 |
| 用 AI 做性能工程 | Agent 读 profile、改源码、复测 | 证据完整性、正确性、测量可信度和可回退候选 |

AI 写源码不改变运行原理。Tracy 不自动提供全部 AI 业务指标，首 Token 和端到端体验等还要额外测量。

## 采集适配

配置构建、运行场景、输入、平台与符号，按需调用 Tracy、perf、ETW/WPR、语言或设备分析器。保存提交、环境和原始记录。免逐函数埋点不等于免配置。

## 证据归一

提取热点 self/total、调用路径、源码、等待关系、区间分布、缺失信息与采样局限。可借鉴 profiler-md，Tracy 命令行导出也可作入口。

v0.14.1 的[官方手册](https://github.com/wolfpld/tracy/blob/v0.14.1/manual/tracy.tex)已包含 Tracy Assist 与可选 MCP 服务。Assist 配置本地模型后在分析界面辅助理解性能数据；独立 Python MCP 服务让编码 Agent 加载、查询和比较 .tracy 记录，需要构建绑定与配置。已有分析接口不等于内置完整测试与源码修复循环；本研究没有调用这些功能。

## 修复与独立验收

~~~text
需求 + 固定负载 → 正常运行测基准 → 定位与证据分析
  → AI 候选补丁 → 编译和业务测试 → 相同场景重复测量
  → 保留 / 修正 / 回退
~~~

正确性与性能分开判断。不能通过删测试、改输入含义或任意放宽阈值通过。深度 profiling 的成本不直接混入正常基准。

输出候选差异、测试、环境、样本、profile、判定与不确定性。

## 可以形成的产品

- 按语言与平台的项目接入向导。
- 基准与噪声感知的回归门禁。
- 慢操作到源码/线程/外部依赖的证据工作台。
- 有次数和成本预算的 AI 优化任务。
- 成功与失败优化的团队知识库。

价值在减少复现、分析、修改和验证的总成本。能力只覆盖已定义需求、负载和环境，不能证明所有输入正确、所有硬件都快。
