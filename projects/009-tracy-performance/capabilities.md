# 能力、效果与接入条件

Tracy 由程序内采集客户端与独立分析器组成，提供实时、远程的混合帧与采样分析。没有帧概念的工具或桌面程序也可使用。

研究依据：[固定 README](https://github.com/wolfpld/tracy/tree/fd23005a67e25f53dd420df6350a2f5907afedc3)和[手册](https://github.com/wolfpld/tracy/blob/fd23005a67e25f53dd420df6350a2f5907afedc3/manual/tracy.tex)。

| 能力 | 效果 | 条件与限制 |
| --- | --- | --- |
| CPU 采样 | 热点、调用路径；条件合适时映射源码/汇编 | 平台、权限、符号、栈展开；不是每次调用起止 |
| 代码区间 | 单次持续时间、嵌套和统计 | 关注的作用域需要埋点 |
| 逐帧 | 帧分布、异常帧与线程活动 | 定义帧边界 |
| 锁与线程 | 等待、获得、释放和线程交互 | 锁接入；调度数据依系统和权限 |
| GPU | 已标记任务的设备耗时 | 对应 API 接入；提交时间不等于设备执行时间 |
| 内存 | 已追踪分配的来源、存活和曲线 | 正确上报分配释放；不等于完整进程 RSS |
| 业务信息 | 日志、数值、程序提供的帧图像 | 由程序发送 |
| 保存与对比 | trace 离线查看、前后对比 | 可比较场景；不自动定义合格阈值 |
| 导出 | 区间统计或逐事件数据 | 测试门禁需要外部系统 |
| AI 分析接口 | Tracy Assist 辅助分析；MCP 向外部 Agent 提供记录访问 | v0.14.1 手册已有说明；分别配置模型或 Python 绑定/服务，不等于自动修复 |

官方直接提供 C、C++、Lua、Python、Fortran 接入，其他语言有第三方绑定。不同语言运行时的采样与源码映射不能直接等同。

## 补充理解：代码来源、语言与运行模式

AI 生成、GitHub 下载、自己编写的代码都可以使用。代码来源不决定适用性；需要语言与平台支持，程序能实际运行，并具有相应采集记录。这里“能控制源码”指能配置工程、集成采集并运行，不要求本人是原作者。

面向对象、过程式、单/多线程、循环、事件驱动和一次性批处理都可采用。Tracy 也能分析没有帧概念的工具与 UI 应用；帧标记是可选的业务边界。源码文本或仓库链接本身不能代替运行。

| 支持层次 | 语言与说明 |
| --- | --- |
| 官方直接接入 | C、C++、Python、Lua、Fortran |
| 第三方绑定示例 | Rust、Zig、C#、OCaml、Odin；绑定维护与版本分别核对 |
| 定位深度 | 采样、调用栈、源码行映射和 GPU 能力由运行时、平台、权限、符号与绑定共同决定 |

C/C++ 常规方式集成客户端并重新编译；分析实际性能时保留优化与调试符号。依赖库的耗时可通过已采集调用栈观察，但无符号或未记录事件会限制解释。Python 接入不等于自动逐行分析全部 Python 代码；浏览器与远程服务内部需要对应采集端。

官方依据：[README 语言清单](https://github.com/wolfpld/tracy#tracy-profiler)、[v0.14.1 手册的 Quick look / First steps](https://github.com/wolfpld/tracy/blob/v0.14.1/manual/tracy.tex)。

## 免业务埋点定位

支持的平台可先用采样找热点，再补关键埋点。Windows 采样需要相应权限和匹配符号；手册平台矩阵中的 macOS 不具备相同自动调用栈采样能力。

CPU 百分比不能定位函数。采样提供执行地址和调用上下文，符号解析映射源码；调度与等待栈补充状态。源码位置是线索，不是根因自动判决。

常规方式仍需集成客户端。固定主分支的 NEWS 在未发布部分新增 Linux tracy-monitor 外部采样；不能将其当作 v0.14.1、Windows 原生或任意语言均已支持的能力。

## 本网页示意

全部帧时间、文件名/行号、区间、锁关系和样本为合成记录。方案推演假定资源预加载与锁外解压，后台工作仍存在；不作为实际性能对比或增益结论。

## 性能保障

完整验收需要可重复负载、预算、环境记录、预热、重复测量和噪声判定。AI 候选还要独立检查业务正确性。

纳秒级分辨率不等于零开销或零误差。环境、硬件、频率、调用栈与事件量都会影响成本；正常基准和深度分析宜分开。
