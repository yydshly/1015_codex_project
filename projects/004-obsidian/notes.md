## 一期实验与问题（历史记录）

**问题**：如何让原作保留实际效果，同时解释扩展方法？

**做法**：完整保留固定上游，依赖本地化，仅加同源控制桥；中文页面提供定格和状态读取。另用 900 个点、固定种子和目标插值演示四种扩展形态，明确不属于上游三维能力。

**观察与结论**：新的视觉轮廓可以由目标点生成器表达；但厚度、法线、采样密度、碎片匹配、材质与镜头仍影响三维完成度。真实科学或装配语义需要对应求解模型或资产信息，不能只换外形。

一期适配差异只有 import map 和消息桥。二期扩展后由 adapt_upstream.py 列出状态、帧更新、相机、焦点、画质与 HUD 的精确钩子；原始上游快照及第三方模块保持哈希一致。verify.py 同时检查本地扩展模块、构建链接和适配输出。

初次浏览器日志出现过一条没有来源 URL 的 MutationObserver 错误；本研究与上游源码没有使用此 API，来源未归因，未阻止演示操作。另外观察到驱动发出的着色器精度 / 优化警告。没有据此宣称所有浏览器或显卡无错误。

一期尚未验证完整视频 / PNG 导出、音频听感、长时间运行、全设备帧率、真实科学精度或全部 WebGL 上下文恢复路径。视频在三期补充实际验证，见后文；未远程发布。

## 二期：原作 GPU 三维扩展

范围：四种扩展共享原作 Voronoi 几何、4 张状态纹理、材质、镜面、阴影与后期，不再绘制独立二维点画布。相同画面内切换模式，不重建 iframe 或第二个渲染器。

实现：CPU 确定性三维表面采样产生位置 / 尺度和四元数目标纹理；原 stateFrag 增加 extensionState 分支。切换保存当前 GPU 位置 / 旋转 / 材质，再向目标过渡。独立时钟控制旋转；速度增量积分避免参数调整引起相位跳变。画质变化按新旧数量重采样 GPU 快照。

自动测试：node --test projects/004-obsidian/tests/extension-shapes.test.mjs。覆盖低 / 高预算的有限坐标、单位四元数、三个轴的空间跨度、确定性、参数对几何的实际影响、文字正反面 / 侧边、厚度 / 宽度和非法输入边界。

## 三期：完整循环、连续镜头与逐帧视频

2026-10-15，新增同一个 GPU 碎片系统中的 48 秒确定性编排：原作 18 秒 → 星系 7 秒 → 龙卷 7 秒 → 双螺旋 7 秒 → 文字 7 秒 → 回归巨石 2 秒。各形态开头的 2 秒同时混合碎片位置、尺度、四元数、材质和镜头；最后逐步恢复完整镜面采样与巨石表面着色，接回开场。

单形态编辑仍保留原来的 1.6 秒交互转场。完整动画改用双目标解析求值，不以上一帧快照为输入，能够任意跳转；导出按同一时间函数计算每帧。镜头包含环绕、升降、文字的缓慢侧移。原作 18 秒中的作者剪辑与镜头切点保留。

视频使用 WebCodecs 和固定 MIT 的 webm-muxer 5.1.4；无声 WebM，720p / 1080p、24 / 30 fps，有限队列与编码背压；包含进度、取消、恢复预览、成片预览和再次下载。该依赖已停止维护，原样保存并带完整许可及哈希；后续扩格式时评估迁移。容器最后一帧时长通过独立 EBML Duration 校正，第三方模块未改。

自动检查扩为 10 项：三维采样属性、文字体积、时间线无缺口、前后跳转 / 周期一致性、过渡端点、相机实际位移 / 连续性、WebM 元数据与偏移保持。适配输出和第三方哈希持续校验。

浏览器已实际执行完整导出与取消：第一次生成 1,440 帧，浏览器视频元数据显示 48 秒、1280 × 720，ffprobe 解码读取 1,440 帧、30/1 fps、VP9；没有跳过或补造帧。检查首尾图像时发现低档镜面子集在回归阶段会产生倒影跳变，随后按权重恢复完整反射和 tiled 着色，并重新导出验证。自定义“星海”已从单形态编辑带入完整动画。

三期结束时，PNG 序列、声音轨道、长时间运行、全部设备 / 编码器、1080p 全流程和 WebGL 上下文恢复尚未实测；四期补充了声音轨道验证。不保证所有浏览器具备 WebCodecs；页面会在不支持时禁用导出并说明。未远程发布。

修正后的完整成片：VP9 / WebM，1280 × 720，30/1 fps，解码帧数 1,440，容器和浏览器时长均为 48.000 秒，30,503,517 字节。文字参数使用“星海”。本地样片保存在 exports/obsidian-complete-48s-720p.webm（忽略提交，可从界面重生成）；关键帧见 assets/film-contactsheet.jpg，首尾对照见 assets/film-seam.jpg，文件 SHA-256 与验证数据见 assets/film-verification.json。

## 四期：原作音效、新形态声音与带声音 MP4

保留原作 AudioEngine 的全部合成声音、固定随机种子、Edit 事件和 Story 驱动。适配器增加可注入的 OfflineAudioContext、输出节点与可调度时钟，没有用其他声音代替原作。完整音轨使用 48 kHz 立体声：原作 0–18 秒、星系泛音 / 星尘钟、龙卷旋转风场 / 低鸣、双螺旋左右声部 / 脉冲、文字细点 / 落定和弦，以及回归原作 resolve。形态对应的两秒窗口交叉淡化，峰值限制与首尾短淡化处理点击声。

试听与导出共用同一个确定性 AudioBuffer：开启声音后从当前动画时间开始，暂停停止音源，跳转 / 倍速 / 单形态切换重新定位。音量用于试听与导出，试听开关与导出音轨勾选项独立。原作原生播放控件也接入声音暂停 / 恢复；播放成片预览时暂停实时演示，避免两份声音叠加。

当前 MP4 / WebM 生成迁移至本地固定的 Mediabunny 1.61.4。原样保存 bundle、对应源文件、MPL-2.0 许可和 SHA 校验，不添加根目录 npm 依赖。WebCodecs 编码 H.264 / AAC 或 VP9 / Opus，音视频都从 0 时刻编码；实际生成速度不改变成片时长。三期 WebM 封装与旧验证材料继续保留为历史记录。

额外校正了减少动态效果模式：上游可能使用 20 秒 Edit，完整作品的原作段统一映射成 18 秒，声音事件时间与速度按同样比例重映射，避免画面与声音错位。对应回归测试通过。

自动检查现为 15 项，新增声音包络连续覆盖、相邻交叉淡化、重映射、有限采样、峰值约束与首尾防点击验证。实际 MP4 用 ffprobe 计数并由 ffmpeg 解码音轨，验证 H.264、AAC、48 kHz 双声道、共同零点、48 秒和 1,440 帧；tools/verify_audio_video.py 可复查，并记录六段音量与声道差异。首版新形态音量偏轻，按实测分段音量调整增益后重新导出，无削波。

操作实测：试听静音时勾选声音，仍能导出 AAC 音轨；音量 70% → 60% → 70%，暂停 / 继续与双螺旋章节定位同步；1080p 导出启动后即时取消，画面与声音均继续播放。WebM 回归导出采用 720p / 24 fps，实际 1,152 帧，VP9 与 Opus 立体声；播放器时长 48.02 秒，包含约 20 ms 的 Opus 编码尾包。

验证不代表逐耳主观听音验收，不保证所有设备具备 H.264 / AAC 硬件或软件编码能力。页面显示实际能力并保留 WebM / 无声选择。PNG、长时间运行、1080p 完整导出和全部浏览器仍未全面实测；未远程发布。

最终 MP4：28,201,791 字节，720p / 30 fps、1,440 帧，H.264 + AAC 48 kHz 双声道；画面与声音均从 0 开始且各长 48.000 秒。样片保存在 exports/obsidian-complete-48s-720p-sound.mp4（本地生成文件，忽略提交），SHA-256、六段音量和浏览器操作检查见 assets/sound-verification.json。四种新形态有效段 RMS 约为 −31.23 / −32.25 / −30.34 / −30.16 dBFS，解码峰值低于 0 dBFS；这是客观电平与音轨验证，不代表主观音质评级。

播放成片预览后，实时演示自动暂停，避免叠音。390 × 844 手机视口下页面 / 滚动宽均为 375px，声音开关、音量、格式、帧率与声音勾选没有造成横向溢出。截图 sound-studio.jpg、sound-mobile.jpg、sound-mobile-export.jpg，成片帧览 sound-contactsheet.jpg。封面同步更新，所有第三方哈希、适配副本、构建资源和索引检查通过。
