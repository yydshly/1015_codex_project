# 004 · Obsidian 程序化碎片变形研究

Obsidian 是基于 Three.js / WebGL 2 的程序化三维视听作品：同一批立体碎片在黑曜石巨石、玻璃教堂和巨鲸之间重组，结合光照、镜面、运镜与合成音效形成约 18 秒的原作循环。

其原理是“表面 Voronoi 碎裂 → 目标曲面采样 → 空间匹配 → GPU 按时间求姿态 → 合并网格与电影化呈现”。当前最直接的价值在电影片头、品牌宣传、发布会开场与舞台视觉；可复用的是组织变化、互动预览与稳定输出的方法。

本研究保留固定版本原作，接入星系、龙卷、双螺旋和立体文字，提供参数调节、48 秒完整声画循环、平滑转场、连续运镜与带声音的 MP4 / WebM 导出。进一步可以扩展标志和产品模型、音乐与数据驱动、互动装置；真实科学模拟与零件装配还需对应模型、数据、身份和约束。

[一图读懂研究结论](web/index.html#understanding)：七张真实渲染效果图，串联能力、五步实现原理、原作与本研究的差异、价值判断、六类用途、十二类扩展方向与能力边界。网页支持缩放、分段定位、PNG / SVG 下载和文字解读；[独立 SVG 总览图](web/assets/understanding/obsidian-understanding.svg) 内嵌全部效果图，也可直接保存 [PNG 长图](web/assets/understanding/obsidian-understanding.png)。

## 为什么研究

1. **视觉叙事**：对象在变化中保持碎片身份连续，适合表达重组、成长、关联与材料循环。
2. **程序化创作**：通过生成规则、采样点与时间表调整作品，减少逐块、逐帧安排碎片动画的工作。
3. **图形工程**：将合并几何、纹理存储状态、GPU 并行、反射和后期组织为可运行样本。
4. **传播与教学**：既展示结果，也能通过暂停、定位与自由镜头解释构成过程。

它的复用价值在于方法与图形模块。新主题仍需完成采样、匹配、运动、材质与镜头设计；上游没有通用模型导入界面、节点编辑器或一键生成任意场景的流程。

## 核心设计与收获

作者以“万物转化”组织叙事。核心代码在一个 `index.html` 中，按 36 秒故事时间编排动作，经变速与剪切映射为约 18 秒循环。

生成碎片 → 从教堂 / 鲸鱼采样目标 → 空间排序匹配 → 时间函数求状态 → GPU 绘制与电影化呈现。

每个碎片在不同形态中的位置、旋转、大小存于纹理，GPU 以当前时间计算状态。主体几何合并为网格，每次对应绘制中一次提交；整帧仍包含状态、主场景、阴影、反射与后期等多个过程。

低 / 中 / 高画质配置的碎片目标为 8,000 / 20,000 / 32,000，网格生成后的实际数量不同；网页读取实际状态显示。碎片会缩放、变换材质，运动由函数编排，作品中的“守恒”是艺术表达，不构成质量或能量守恒的数值验证。

## 可扩展现象与场景

| 层次 | 可扩展现象 | 适用场景 |
| --- | --- | --- |
| 形态 | 文字 / 标志聚合、建筑生长、晶体与双螺旋、产品装配 | 品牌首屏、建筑展陈、结构教学、产品培训 |
| 运动 | 星系盘、龙卷、鸟群 / 鱼群、波传播、冲击与涟漪 | 天文 / 气象主题、舞台、自然行为示意 |
| 输入 | 音乐驱动聚散、指针吸引与排斥、真实数据点重组 | 音乐可视化、互动装置、数据故事 |
| 叙事 | 材料回收、资源到产品再到新产品的连续转化 | 环保展陈、品牌循环主题、公益传播 |

星系、龙卷、双螺旋和文字已经接入原作三维系统，其余方向仍为研究建议。新形态复用同一份 Voronoi 碎片几何，通过新增浮点目标纹理与 GPU 状态分支驱动；切换时保存当前 GPU 姿态，在 1.6 秒内过渡。暂停时修改形态参数直接显示结果。三维文字包含正面、背面与侧边采样，可用自由镜头检查厚度。

新增效果是程序化视觉演示。严谨的天体、流体、群体行为或材料实验，还需对应模型、单位、数据与验证。

完整动画有独立的确定性时间线。原作部分保留作者约 18 秒剪辑，四种新形态各占 7 秒，最后 2 秒重聚巨石；GPU 同时求出相邻形态的状态，以五次平滑曲线混合位置、尺度、朝向与材质。镜头沿解析路径环绕 / 升降，并使用同一曲线衔接。拖动、倒放定位与逐帧导出都按同一时间求值，不依赖先前播放过程。

视频在新版 Chrome / Edge 的 localhost / HTTPS 页面本地生成，默认输出 H.264 / AAC 立体声 MP4，也可选 WebM 或关闭声音。试听与导出共用离线合成的 48 秒音轨，使用上方音量；试听静音不影响导出声音勾选项。输出使用编排镜头，不含网页界面，当前自由视角不写入视频。完整操作说明见 [网页说明](web/README.md)。

建议按“替换一种形态 → 扩展运动 → 接入输入 → 按设备和场景交付”推进。[完整扩展矩阵](extensions.md)给出 12 类方向的输入、改造、场景与难度。
