# 实现原理与本地接入

研究依据：[固定版本源码](https://github.com/iamtechartist/obsidian/blob/74510f112c0a7e4318f688b851523105ec4f79e4/index.html)，原始快照见 [references/upstream-index.html](references/upstream-index.html)。以下行号对应原始版本。

## 数据流

```text
CONFIG + 固定随机种子
  ├─ 巨石 → Voronoi 碎裂 → 有厚度的碎片几何 + 原位姿态
  └─ 教堂 / 鲸鱼 → 曲面与轮廓采样 → 空间排序匹配 → 目标纹理
                                                        │
真实循环时间 → Edit.story() → 故事时间 T → GPU 状态求值
                                                        │
                    位置/尺度 + 四元数 + 材质 + 速度/阶段
                                                        │
                    合并网格按 ID 读取 → 主场景/阴影/反射
                                                        │
                    光束、热扰动、辉光、景深、调色 → 输出
```

## 碎裂：表面分割与立体化

巨石侧面展开为周期二维带，顶盖使用独立二维区域。网格种子由整数哈希扰动，用邻域种子的平分线裁切 Voronoi 单元。跨倒角的区域沿折线拆成平面片，使表面接缝一致。

区域向内挤出成为立体碎片。顶点保存局部坐标、碎片 ID 与边界距离，参与倒角、玻璃边缘和发光。完整巨石的裂纹使用相同哈希规则，碎裂与回归的轮廓因此对应。见 L508–881。

## 采样与匹配：安排每块碎片的目的地

教堂通过带孔墙面、拱顶、尖塔和线条构造；鲸鱼用截面曲线与鳍部曲面构造。它们主要作为采样模板，不是最终显示的一整个实体网格。

MeshSurfaceSampler 按面积 / 权重采样，Halton 序列减轻随机聚团。拱门、肋骨、尖塔与玫瑰窗额外分配点数，保留低碎片数下的识别性。见 L883–1381。

bandMatch 先按主键排序并分带，带内按角度配对。巨石底部对应基础，顶部对应尖塔；教堂高处先脱落的碎片对应鲸鱼头部。它保持大体空间关系，不保证全局最优。见 L1217–1247。

## 运动：状态是时间的函数

位置、旋转、尺度、分组和随机数存入宽 256 的 Float DataTextures，通过碎片 ID 定位。GPU 状态着色器接收故事时间，计算爆散、涡流、群舞、搭建、鲸鱼、螺旋和锁定等阶段。

贝塞尔曲线衔接轨迹，四元数插值结合端点归零的翻滚项，延迟由高度 / 排名决定。鲸鱼另加身体摆动、鳍部动作、路径姿态和离地约束。见 L1670–2002。

中 / 高档再次求 T − 1/60 的位置以差分估计速度，仍属于解析求值，没有必须逐帧积分的物理状态。因此能直接定位和确定性重放。若改用有历史状态的流体 / 群体模拟，需另做固定步长、重置、缓存与回放。

## 绘制：合并网格与多个渲染过程

离屏状态过程输出四张浮点纹理。全部碎片是同一个合并网格，顶点按碎片 ID 读取状态并放置。主场景、深度、阴影与镜面共享状态；反射可减少碎片子集和分辨率。见 L2005–2010、L2910–2977。

“主体碎片一次提交”不等于整帧一次 draw call。后期依次处理太阳光束、玫瑰窗光束、热扰动、辉光、景深、调色与输出。见 L3176–3211。

## 时间与循环

动作基于 36 秒故事时间；CONFIG.edit 列出片段与真实时长。Edit 用分段 Hermite 曲线变速，片段空缺产生剪切，实际循环约 18 秒。结尾对齐镜头、云、水面和裂纹状态。见 L271–482、L3331–3343。

## 本研究页如何接入

- `web/vendor/obsidian/index.html`：完整上游通过明确钩子接入扩展；原作模式与 GPU 扩展共用渲染器、场景、碎片网格、状态目标、镜面、阴影和后期。
- `tools/research_bridge.js`：校验消息来源与 origin，执行形态、参数、播放、画质与镜头操作，报告目标数、实际网格顶点数、状态纹理数和模式。
- `web/assets/studio-controls.mjs`：同一个画面旁的中文模式与参数面板。`web/app.js` 保留内容筛选和原理说明。关闭演示才卸载 iframe；切换形态不创建第二个渲染器。
- `web/assets/extension-shapes.mjs`：确定性三维表面采样，输出与实际碎片数相同的位置 / 尺度和四元数。三维文字先提取像素正反面与轮廓，再生成有厚度的目标。
- `web/assets/extension-system.mjs`：附加目标 DataTexture、GPU 当前姿态快照、状态着色器分支、独立时钟、镜头和质量切换重采样。
- `tools/adapt_upstream.py`：离线应用每个精确匹配的钩子；验证器比较生成结果，原始快照与第三方模块仍按哈希校验。
- `tools/vendor_upstream.py`：固定提交、校验 npm 包 SHA-512、保存必要模块闭包与许可证。

可复用接口建议：`ShapeSampler → Assignment → MotionStage → Renderer → Director`。新形态至少输出位置、法线、尺度、分组；外部模型还需归一化、轮廓采样与加载错误处理。外部输入先映射到有界参数，再驱动材质和运动。

## 四种形态接入 GPU 的具体路径

```text
模式 / 参数 → 三维表面采样 → 位置·尺度 + 四元数 DataTexture
                                    │
当前 GPU 状态 MRT → 三附件 GPU 快照 ──┤
                                    ↓
原 stateFrag 中的 extensionState 分支
  ├─ 根据独立时钟计算旋转、差速、扰动与聚合
  ├─ 从当前姿态过渡至新目标（1.6 秒）
  └─ 写回原来的位置、四元数、材质、速度四张纹理
                                    ↓
原 Voronoi 碎片合并网格 → 原阴影 / 镜面 / 材质 / 后期
```

模式之间固定沿用碎片 ID，避免切换时重新创建碎片。改变几何参数会重新采样目标并保存当下 GPU 姿态；聚合、大小、速度和扰动通过统一参数控制。旋转角度增量积分，调整速度不会因 `时间 × 新速度` 发生相位跳变。

切换画质会更换实际碎片数量，GPU 快照按新旧数量比例重采样，随后向新目标过渡。参数都限制范围；不支持的字形会返回明确错误。暂停不推进独立时钟，但参数更新会立即呈现，摄像机仍可操作。

## 48 秒完整动画与视频

`tour-timeline.mjs` 定义六个连续区间：原作 0–18、星系 18–25、龙卷 25–32、双螺旋 32–39、文字 39–46、重聚巨石 46–48。每个新阶段最初 2 秒使用 `6t⁵−15t⁴+10t³`，端点速度和加速度为零。原作仍沿用作者的 Edit / Story；扩展时固定原作故事在巨石起点。

`tour-system.mjs` 为四种形态各保存目标纹理。状态着色器把原函数保留为 `originalShardState`，包装层按当前时间分别求出相邻形态，混合位置 / 尺度 / 材质并对四元数球面插值，写回原四张 MRT。与交互模式的 GPU 快照不同，完整循环的结果不依赖前一帧，因此支持任意跳转。原作区间继续使用其 tiled / solid 几何；扩展和回归阶段沿用同一碎片网格。

镜头解析路径包含绕场、升降和文字的缓慢侧移。相邻镜头按同一过渡权重混合位置、焦点、视角和景深；回归阶段接回作者开场镜头。完整循环禁用额外手持 / 鼠标视差，保持定位与导出一致；自由视角仍可用于预览观察。光照范围和材质控制也在巨石边界按权重衔接。

`film-exporter.mjs` 在所选尺寸固定画质，按 `i / fps` 驱动同一个 tick，使用 Mediabunny CanvasSource / WebCodecs 编码，逐步等待背压并让出界面处理取消。音轨从时间零点编码，与 48×fps 个视频帧合并为 MP4（H.264 / AAC）或 WebM（VP9 / Opus）。完成 / 取消 / 失败后恢复预览位置、尺寸、播放状态、自由视角和声音。不采集麦克风或桌面。三期的 webm-muxer 与独立容器时长修正保留为历史材料，当前封装由 Mediabunny 处理。

这两条路径不改变原始快照。适配器声明的精确钩子、目标模块、封装依赖和许可均由验证器检查。

## 同一份 48 秒声轨如何用于试听与 MP4

`AudioEngine` 仍保留作者全部声音生成函数与事件。适配器只增加可注入的 AudioContext / 输出节点、可调度的 `now()` 时钟和试听音量；原有实时调用仍用当前 AudioContext 时间。`film-soundtrack.mjs` 将这一个合成器接入 48 kHz 双声道 OfflineAudioContext，按 Edit 的真实事件位置触发碎裂、钟鸣、鲸歌等，并用 60 Hz 的 Story.lava / bullet 参数驱动连续底声，无需重新实现原作声音。

四种新声音采用有界的振荡器、带通噪声、左右声像、包络和混响，与作者的确定性脉冲响应共享空间感。星系是柔和泛音 / 星尘钟，龙卷是带通风噪 / 低鸣，双螺旋是左右交替三角波 / 低频脉冲，文字是短促细点 / D 大调和弦。各声部在与形态相同的 2 秒窗口交叉淡化，46 秒重新引入原作低鸣和 resolve。按段落平衡增益，经压缩、峰值限制和 12 ms 首尾防点击处理后形成缓存 AudioBuffer。

试听用 AudioBufferSourceNode 从当前动画位置启动；暂停停止音源，定位 / 倍速 / 模式变化重定位，循环点回到 0。单形态模式循环对应稳定段落。导出把同一 AudioBuffer 按当前音量送入 AAC / Opus 编码器，音轨与视频均从 0 开始，生成速度与系统播放时间无关。试听静音与是否导出声音分开控制，不会因为浏览器自动播放策略而静默丢掉导出音轨。

Mediabunny 1.61.4 的原样 bundle、对应源文件和 MPL-2.0 许可均本地保存并校验；不修改其源文件。编码器能力在浏览器中实际探测，缺少某格式时给出可操作提示。
