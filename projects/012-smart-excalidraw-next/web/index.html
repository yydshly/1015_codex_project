04 / CAPABILITIES & LIMITS
“把任意内容给它”，要满足什么？
覆盖面可以很广。先把输入、表达和执行这三件事说清楚。
01
内容要能被读到
文字、MD / TXT 与图片有现成入口。数据库、Excel、仓库链接和外部 API 的内容，需要先提取为输入，或另外开发连接器。
输入边界
02
信息要有可表达的结构
层级、步骤、时间、因果、关联最适合画成图。数值先准确计算，模型补充的内容与业务关系仍需要核对。
准确性边界
03
能力描述可以变成图
提供“搜索、抓取、总结”的能力说明，可以画出工作流。真正执行搜索和抓取，需要另接工具与业务系统。
执行边界
复杂排版需要人工整理
当前箭头优化主要调整绑定端点；没有完整的全局避障与节点自动排版实现。
生成请求采用单轮输入
当前画布和对话历史没有作为完整上下文发送给模型，持续对话修改现有图需要扩展。
部署位置与模型位置分开看
本地运行网页时，生成内容仍会发送到所配置的模型端点。自带 Key 模式的配置会经过应用服务端。
知识图解与专业计算各有分工
甘特、漏斗、矩阵等提供图形表达；日期计算、统计口径与实时数据更新需要另行处理。
WHERE THE VALUE IS
把画图的起点，从空白画布变成可讨论的初稿。
适合需求沟通、技术文档、教学说明与项目研究。保留结构，方便精修，也方便下一次修改。


  
05 / EXTENSION SCENARIOS
从画一张图，到接入实际工作。
以下是基于当前能力的扩展建议，需要额外接入和开发。
扩展方向 · 待开发
01 / 数据接入
让业务资料自动成为输入
把数据库表结构转成 ER 草图，把项目文档转成架构图，把工单规则转成流程图。
需要：读取器、权限范围、数据提取与准确性校验。
02 / 行业模板
让同类图保持一致的表达
为审批、技术方案、培训或项目研究沉淀图形模板、术语表、配色和图标资产。
需要：模板系统、行业语义和统一的视觉规范。
03 / 持续改图
让图跟着需求一起变化
带上当前画布与修改要求，针对某个节点或分支生成差异，再审阅与应用修改。
需要：画布上下文、多轮会话、差异与撤销机制。
04 / 团队协作
让图成为共同讨论的资料
在团队内管理方案版本、批注与评审，复用经过确认的图形和业务表达。
需要：账号权限、持久存储、版本管理与协作功能。
05 / 业务闭环
让计算、工具与图形配合
由业务系统计算数据、执行任务，再将结果整理成状态图、时间计划或报告配图。
需要：工具接口、计算校验、更新触发与错误处理。
