## 1. 视频流量到底由谁支付

| 方式 | 视频字节路径 | 你的费用 | 主要约束 |
| --- | --- | --- | --- |
| 官方播放器嵌入 | 来源平台 → 浏览器 | 网站和业务开销；按平台条款可能无需自付媒体费 | 播放器、广告、收费和地区规则 |
| 上游媒体直连 | 上游 CDN → 浏览器 | 网页和 API 为主 | 是否允许接入、上游额度、用户网络 |
| 自家服务转发 | 上游 → 你的服务器 → 浏览器 | 全部转发出站带宽及连接资源，可能还有上游费 | 双边额度、网络、预算与代理安全 |
| 自有文件＋视频 CDN | 你购买的存储/CDN → 浏览器 | 许可、存储、转码、分发和业务费用 | 合同范围、服务价格和质量 |

用户停留在你的网站观看，并不意味着视频经过你的网站服务器。007 的正常 UI 使用上游直连地址；可选 `/media/` 转发入口未用于普通播放。

免费内容许可可以让内容费为零。自行保存和分发的计算、存储、网络仍有成本；某些平台或套餐提供免费额度，需要按适用规则看待，不能推成无限免费。

## 2. 流量、带宽和并发分开算

本文使用十进制：1 GB = 10^9 字节，1 Mbps = 10^6 位/秒。平均总码率应包含视频和音频。

```text
每次观看流量 GB = 平均码率 Mbps × 实际传输分钟 × 60 ÷ 8 ÷ 1000
月视频流量 GB = 每次观看流量 × 次数 × 额外传输系数
并发所需带宽 Mbps ≈ 平均码率 × 同时播放人数 × 余量系数
实际分发费 = 各地区流量 × 各地区单价之和
```

例如平均总码率 3 Mbps，每小时约 1.35 GB；100 人同时播放约需 300 Mbps 的纯媒体带宽。100 人每天各看 1 小时，30 天约 4.05 TB。它们是算术情景，不是 007 实测码率和容量。

5 Mbps 的服务器出口不能因为 CPU 空闲就承诺几十人同时看 3 Mbps 视频。自家后端只返回播放地址时，服务器带宽则不直接决定上游 CDN 的播放人数。

额外传输来自缓冲、预加载、重复拖动、重试和异常请求等。CDN 命中可以降低回源负载，但观众接收到的字节通常仍计入 CDN 分发账单。

## 3. 流量限制有哪些

| 限制 | 影响 |
| --- | --- |
| 搜索 API 每秒/每日额度 | 搜索和详情可能受限，不等于观看容量 |
| 上游单 IP 并发 | 转发或集中请求可能更快触发限制 |
| 来源域名、Referer 或地区 | 浏览器接入可能被允许或拒绝 |
| 签名有效期 | 老播放地址可能过期，需重新签发 |
| 总流量或余额 | 超额度、余额不足后可能停服或加收费用 |
| 实时网络吞吐 | 没超月流量，也可能因高峰带宽不足而卡顿 |
| 编码和设备 | 线路畅通但解码不兼容，仍无法观看 |

未知公共源的 CORS 放开不代表没有这些限制；代理也不会自动消除限制或取得许可。

## 5. 可复现的成本情景

假设转码后存储共 20 GB、片库时长 200 分钟、每次实际传输 10 分钟、平均总码率 3 Mbps、额外系数为 1：

| 月观看次数 | 流量 GB | Bunny Volume | Bunny 欧美 Standard | Bunny 亚洲 Standard | Cloudflare Stream |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100 | 22.5 | $1.00 | $1.00 | $1.00 | $6.00 |
| 1,000 | 225 | $1.33 | $2.45 | $6.95 | $15.00 |
| 10,000 | 2,250 | $11.45 | $22.70 | $67.70 | $105.00 |

金额含上述服务的假设存储与最低消费，按常用财务四舍五入展示。未计域名、网站、内容许可、支付、字幕、营销、人力、跨云搬运、税费和可选服务；不是整站报价。各地区混合观看需按实际分布加权，不可全部套欧美价。小数算式和假设由 [成本工具](tools/estimate_cost.py)输出。

```powershell
python projects/010-zhuiju-product-research/tools/estimate_cost.py --plays 1000 --minutes 10 --mbps 3 --storage-gb 20 --catalog-minutes 200
```

如改为 90 分钟长片、较高码率或大量预加载，费用会显著变化。实际经营应使用真实的每观看小时成本和转码后资产占用。

## 6. Filmhub 文件交付的额外预算

标准方案支持把文件推送到你的 AWS S3 或 SFTP 等接收端；S3 文档指定真实 AWS S3、us-east-1，不支持把兼容 S3 的任意存储当成相同接收目标。需要把“接收原片”和“面向观众分发”分别设计。[交付说明](https://help.filmhub.com/en/articles/2692190-setting-up-file-transfer)

可能的流程是 Filmhub → 接收存储 → 导入视频服务 → 转码/打包 → CDN。接收存储、原片保留、跨云传输及再次处理均应询价。文档提示个别交付文件可达 70 GB，这不是每部平均大小，但说明不应按压缩后的播放片段大小估计接收空间。

具体承担方仍以渠道合同为准，不能把 Filmhub 的交付编码服务当成包含所有终端观看流量。

## 7. 从本地到生产的合理部署

### 阶段 A：本地技术验证

保留 007。适合开发和有限抽样；不把 localhost 地址登记为公网 Demo，不把本机 DNS 特殊规则搬到生产。

### 阶段 B：有授权的小片库试点

```text
域名 / HTTPS / 静态页面
        ↓
小型生产 API＋片目数据库
  负责：搜索、详情、授权可用范围、播放会话、质量事件
        ↓ 返回播放 ID 或签名地址
浏览器 ─────────────────→ 视频服务 / CDN
```

可以从 1～2 核、1～2 GB 内存的应用环境做小规模测试，这是配置建议，不是容量保证。网页和 API 同域可简化接入；具体生产服务框架按团队熟悉程度选择。视频大流量不经过业务后端。

先不引入复杂微服务、搜索集群或多 CDN。小片库可以从简单数据库和导入脚本起步。管理密钥留在服务端；媒体服务设置必要域名限制和预算，缓存与来源台账按合同管理。

### 阶段 C：验证需求后扩展

根据实测增加后台导入队列、转码事件处理、数据库、检索、多区缓存和供应商冗余。供应商或 CDN 切换需保持作品与授权一致。不要因为搜索慢就盲目增加视频服务器，也不要因 CDN 卡顿只升级业务 API。

本研究未运行上述生产环境，也未购买相关服务。

## 8. 静态托管不等于视频分发套餐

研究文档可以沿用仓库现有 Pages 机制；需要运行时 API 的正式应用应单独托管。GitHub Pages 是静态托管，且官方对商业用途和容量有适用限制，不能直接作为任意商业视频网站的后端与片库。[GitHub Pages 限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

Cloudflare Pages 的静态资源请求和 Functions 是不同计费范围；静态请求免费规则不能推广为无限视频代理。Cloudflare 普通 CDN 对视频与大文件有专门条款，应使用适用的视频或开发者服务。[Pages 计费](https://developers.cloudflare.com/pages/functions/pricing/)、[CDN 条款](https://www.cloudflare.com/service-specific-terms-application-services/)

## 9. 质量与预算怎么验收

- 按目标地区、网络和设备测试首帧、卡顿、播放失败及拖动；服务器能取到文件不代表用户播放顺畅。
- 初期并发目标可以设为 20 人，属于待验证目标，不是当前已通过的测试。
- 同时采集播放端事件和服务端/CDN 用量，区分页面打开、有效播放、传输时长和完整观看。
- 设置余额/预算告警、月流量限额、合理预加载和有限重试；配置是否硬性停服及传播延迟应在具体服务中验证。
- Bunny 公布 99.99% 平台可用性及补偿条款，但不代表所有地区均无卡顿，更不是本项目实测结果。[SLA](https://bunny.net/sla/)

短时签名和来源限制用于控制自己付费的分发入口，不能用来违背开放内容许可。商业版权片是否需要 DRM、地域控制和下载限制应由合同确定。

## 10. 算利润需要加入内容和获客

```text
贡献利润 = 可确认收入
         − 内容分成或许可费用
         − 视频存储、处理、分发
         − 支付、退款、广告或渠道费用
         − 可归因获客和服务成本
```

分成基数和扣除项必须按合同定义。低视频账单不等于盈利；广告填充率不足时用户仍产生流量，但广告收入可能为零。先验证收入机制，再用留存与贡献利润决定是否扩大内容和流量。
