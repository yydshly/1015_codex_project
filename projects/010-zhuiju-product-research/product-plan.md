# 产品定位、差异化与盈利验证

[返回总览](README.md) · [片源获取](source-acquisition.md) · [成本](distribution-and-cost.md)

本页是建议方案，日期为 2026-10-16。预算、样本量和指标是供决策的起始假设，不是行业基准，也不是已经取得的经营成果。

## 1. 当前明确的目标

- 用户在本网站搜索、选择作品或集数并观看。
- 从低成本试验开始，不预先承诺建立热门电影剧集全覆盖片库。
- 地区可以选择，首版接受动画短片和专题内容。
- 内容与分发的使用条件可确认；不把未知公共源当成长期供应合同。

## 2. 三种可选产品

| 产品 | 用户为什么来 | 收入方向 | 难点 |
| --- | --- | --- | --- |
| 资源发现与状态目录 | 少找入口、知道是否可访问 | 赞助、明确标识的广告、适当合作推广 | 内容质量与持续维护、用户愿付费程度 |
| 动画短片精选与解析 | 有限时间发现好作品，并理解制作和主题 | 原创解析、学习资料、专题会员、活动或赞助 | 持续授权、编辑质量和需求强度 |
| 商业片库视频站 | 稳定、方便地观看一类足够丰富的作品 | AVOD、SVOD、TVOD 按授权选择 | 供应合同、内容与流量成本、规模与获客 |

当前优先第二种。原库的主要参考对象是第一种；007 验证第二、三种的一部分技术；Filmhub 是第三种的供应商候选。

## 3. 差异化应该可被用户感知

| 方向 | 具体做法 | 如何验证价值 |
| --- | --- | --- |
| 明确主题 | 如“10 分钟内的动画叙事”“无对白短片”“动画镜头学习” | 主题页到有效播放、收藏和复访 |
| 原创编辑 | 看点、背景、制作解析、作品之间的关联 | 解析阅读完成与后续观看行为 |
| 语言与易用性 | 有权使用的字幕、清晰片目、移动端、键盘操作 | 字幕使用、错误率和访谈 |
| 时间与选择成本 | 按时长、情绪、题材和观看目的筛选 | 找到合适作品所需时间 |
| 可靠性 | 有效授权、播放质量、失败提示、可用范围 | 首帧、卡顿、失败及投诉 |

不要先把“有搜索框、接很多接口、页面干净”作为独占优势。公共接口和通用 UI 容易被复制；丰富目录也不等于有相应权利、播放质量或内容需求。

## 4. 首版功能范围

| 必需 | 延后 |
| --- | --- |
| 片目、题材/时长筛选、搜索、详情 | 全网聚合和自动爬取 |
| 站内播放、授权署名、字幕 | 多供应商自动择优切换 |
| 明确错误、播放质量事件 | 复杂个性化推荐 |
| 本地收藏/观看进度，必要时最小账户 | 社交、弹幕、上传社区 |
| 片目导入、到期与下架开关 | 多端 App、电视端和复杂会员等级 |
| 成本和来源台账 | 自建转码集群和多 CDN |

先接少量授权影片。可以复用 007 的交互思路，但应把数据源换成自有片目与获准分发资产，完成生产化后再开放测试。

## 5. 内容增长路线

1. **起步作品**：从 Big Buck Bunny、Sintel 等已核实许可的具体影片开始，按片保留许可证、署名和完整片尾。
2. **扩充到 5～10 部**：逐片核实授权和相关素材，不把目标数量写成已经具备。
3. **直接作者合作**：与独立团队谈非独家专题播放、收益分成或限定活动；明确字幕、剪辑、海报和地域等权利。
4. **商务片库试点**：向 Filmhub 等申请目标题材的少量片单和完整报价，不预先购买未知容量。
5. **稳定后扩展**：用观看和复访数据决定下批采购，而不是只追求片目数。

对于开放作品，可以收费提供原创策展、解析或服务，但必须保留用户在原许可证下的权利，不暗示影片独占。对于官方嵌入平台，收费范围需按平台条款审查，例如不能对 YouTube 嵌入播放本身收费。

## 6. 30 天低成本验证建议

| 阶段 | 具体工作 | 应形成的证据 |
| --- | --- | --- |
| 第 1～3 天 | 定一个主题，访谈 5～10 个目标观众；建立来源台账，挑选获准作品 | 用户原话、许可依据、主题假设 |
| 第 4～7 天 | 上线小片库最小流程；配置分发预算，验证目标网络和设备 | 授权片单、播放记录、初始每观看小时成本 |
| 第 8～14 天 | 邀请首批约 20 人，修复首帧、字幕和搜索问题 | 实际使用与访谈，不只统计访问量 |
| 第 15～21 天 | 发布 3 个原创专题或解析，尝试可归因的自然传播 | 各专题有效播放、复访和获取用户的成本 |
| 第 22～30 天 | 提供一个明确收费项或赞助方案，按规则开展小额真实试验 | 订单/退款或明确拒绝理由、贡献利润 |

这些步骤尚未执行。不得用“用户可能喜欢”或点击购买按钮代替真实付款；不虚构成交、观众或收入。

## 7. 预算如何设

| 预算项 | 首轮建议 | 说明 |
| --- | --- | --- |
| 已核实开放影片许可 | 许可费可为 0 | 仍有署名、核验和编辑工作 |
| 视频服务 | 先设 $10～20/月试验额度 | 不是不限量套餐，按真实用量变化 |
| 域名与网页/API | 按实际方案单列 | 不把内容分发预算当成整站总成本 |
| 商业片库 | 未获报价前不预填低价 | 许可费、分成、保底和交付需确认 |
| 推广 | 先自然传播与邀请 | 后续付费获客必须单独核算 |
| 人力 | 记录编辑、字幕、维护工时 | 小团队最容易忽略的成本 |

若采用 Bunny，可以小额预付并设置用量限制；Cloudflare 可作为按分钟预算对照。源站、地区、字幕和合同要求不同，最终技术选择应以试播结果和完整费用确定。

## 8. 需要采集的指标

| 指标 | 建议定义 |
| --- | --- |
| 有效观众 | 去重后实际播放至少 30 秒；短于 30 秒作品另定规则 |
| 起播成功率 | 发起有效播放后，在限定时间内出现可解码首帧的比例 |
| 首帧时间 | 用户播放操作到首个画面的时间，报告分位数 |
| 卡顿比例 | 卡顿时间 / 有效播放时间，按来源、地区和设备分组 |
| 完播与观看深度 | 看过作品时长比例，区分短片和长片 |
| 7 日复访 | 同一观察队列在定义窗口内再次有效使用 |
| 收入 | 实际确认的广告、付款或赞助，扣除退款并标明口径 |
| 内容贡献利润 | 收入减内容、分发、支付及可归因运营费用 |
| 获客成本 | 可归因支出 / 新增有效观众或付费用户，口径分开 |

最小事件可包含 `search_submit`、`title_open`、`play_intent`、`first_frame`、`play_error`、`watch_progress`、`return_visit` 和实际支付回调。避免将一次刷新或播放器重复重试算成多个观众；按需要最少收集数据并明确告知用途。

## 9. 怎样决定继续、调整或停止

以下是小样本讨论用的建议门槛，应结合访谈调整，未被实测证明：

- 先争取 20 位真实目标用户，并完整收集主要播放失败原因；20 人无法推出市场规模。
- 修复明显技术阻碍后，观察至少两个使用周期，区分“没需求”和“播放失败所以离开”。
- 若有稳定复访、用户主动要求新增作品，并且出现真实付费或明确赞助意向，再扩片库。
- 若用户只在有热门新剧时愿意来，而供应合同无法支持该需求，调整定位；继续增加开放短片不能自动解决错配。
- 若每观看小时的贡献持续为负，先检查变现与分发成本，不用低价采购假设掩盖问题。
- 若供应方条件、字幕成本或内容匹配度不成立，不为拿到更多片目而接受不可承担的保底。

## 10. 各种收益方式的适用条件

| 方式 | 可能收入 | 必须满足 |
| --- | --- | --- |
| 赞助/广告位 | 按曝光、周期或合作付费 | 有真实受众，清楚标识广告，不把付费伪装成中立评分 |
| 原创资料与解析 | 专题包、课程、会员 | 内容和所用片段/字幕具备适当权利，用户认可价值 |
| 商业影片订阅 | SVOD 收入 | 片库明确支持订阅、能算分成及支付成本 |
| 单片租售 | TVOD 收入 | 取得对应权利并管理观看期限和订单 |
| 视频广告 | AVOD 收入 | 广告需求、实际填充、可报告收入和相应播放授权 |
| 合作推广 | 合同约定的推广收入 | 服务适用，披露关系，核实供应方条件 |

上游 README 当前有标注为商业广告的运营支持位。这能证明其使用了广告展示方式，不能证明广告成交、点击转化或盈利金额；不要从一个广告位估算实际收入。[固定 README](references/upstream/README.md)

## 11. 实施顺序

先确认题材和首批来源 → 整理片目与授权 → 完成最小站内观看 → 做目标网络测试 → 小规模邀请和原创编辑 → 取得真实收入证据 → 再谈大片库和技术扩容。

已有的 007 可以降低最小交互开发成本；010 的文档和来源表用于减少决策误解。当前没有生产部署、商业采购和盈利结论。
