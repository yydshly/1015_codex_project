# 010 · 追剧资源库与视频产品全链路研究

研究对象：[laoma528/awesome-zhuiju-free](https://github.com/laoma528/awesome-zhuiju-free)。本项目汇总本轮对话、源码阅读、007 的真实搜播实验，以及内容授权和视频分发服务的官方资料，回答“这个库有什么用”和“怎样据此做一个能运营的视频产品”。

**摘要：**源库用结构化 JSON、社区推荐、维护者审核和定时 HTTP 检测维护影视资源入口。我们从配置发现影片 API，验证搜索、详情、选集和 HLS 播放；进一步把同类产品拆成内容许可、片目与接口、前端观看、存储/CDN及质量与收入验证五层，给出低成本起步路线。目录、播放成功和商业授权各自需要证据。

**核心结论：这个库是一套公开的资源发现、整理和维护系统。它提供寻找网站、播放器与配置的线索；站内搜索、影片播放、内容授权和视频分发，需要另外实现或采购。**

**网页研究版：**[打开交互研究网页](web/index.html)，或按 [Web 运行说明](web/README.md)启动本地预览。八个章节串起库的能力、我们的探索、片源发现、分发成本、Filmhub 与产品路线，包含 11 篇完整资料的站内阅读器。

## 用户目标与范围演进

最初问题是理解一个免费追剧资源仓库，随后明确希望“在自己的网站搜片、选集并直接播放”。我们先完成了真实来源抽样和最小 Demo，再讨论内容供应与成本。当前接受“地区不限，可以先做动画短片或专题内容”，所以商业起步可以采用较小、可授权的垂直片库。

这里保留两条路线：技术验证继续参考 007；正式产品以明确授权或允许嵌入的内容起步。前者的播放成功不替代后者的供应合同。

## 这个库的能力是什么

上游把资源保存在结构化 JSON 中，区分分类、访问条件、评分、风险、核验记录、提交来源和精选状态；再通过脚本生成 README，结合 GitHub Actions 更新可访问状态、开源项目数据和周报。社区通过 Issue 推荐，维护者审核后由自动化写入资源记录。[源码解读与固定文件](capabilities.md)

## 已经取得了什么效果

007 从原库收录的“小马”配置中找到“暴風”HTTP 接口，独立实现了搜索、详情、选集和 HLS 播放。样例返回 8 集，首两集在浏览器中出现实际 1920×1080 解码画面并推进播放时间。适配器 6 项测试及实时链路 9 项检查的历史记录保存在 007。

同时记录了历史条目 404、部分分片超时和拖动后缓冲。没有完整观看全片、遍历全片库或做多地区并发压测。本研究归纳时未重新声称该源仍然稳定可用。[007 实测与限制](../007-zhuiju-source-demo/README.md)

## 实际发现的来源链路

```text
awesome-zhuiju-free/resources/resources.json
  → tvbox_config 分类中的“小马”
  → https://szyyds.cn/tv/x.json
  → sites 中 key=暴風、type=1 的 HTTP 接口
  → https://bfzyapi.com/api.php/provide/vod/
  → 详情中的 vod_play_from / vod_play_url
  → v.fengbao14.com 的 HLS 清单和媒体分片
```

这条链路解释了我们如何找到接口和视频 URL。影片最初由谁取得、上游为什么承担成本、是否允许第三方商业分发，本次没有证据确认。原库核验记录中明确存在用户提交和截图推荐，因此只能追溯到目录收录和配置，不能从 `submitted_by=maintainer` 推断原始影片出处。[完整来源分析](source-acquisition.md)

## 参考价值在哪里

1. **资源情报和市场研究**：观察用户寻找什么、已有产品怎样组织、入口如何变化。
2. **可维护的数据目录**：JSON 作为单一数据源，展示、检测和审核分工，适合复用到其他资源导航项目。
3. **接入实验起点**：从配置发现接口，练习标准化搜索、详情、线路和播放器；需要独立验证。
4. **运营设计样本**：来源追溯、社区贡献、失效处理、更新记录比一次性网址合集更有用。
5. **边界识别**：URL 可访问、媒体可播放、授权可商用、服务可持续，是分别需要证据的状态。

真正的产品壁垒应落在可持续的内容供应、专题选择、质量、使用体验和用户关系上。普通搜索框、选集按钮和同一批公共接口很容易重复实现。

## 如果实现类似产品，需要选哪种路线

| 路线 | 最先需要什么 | 视频流量通常由谁承担 | 起步判断 |
| --- | --- | --- | --- |
| 资源导航与状态目录 | 可维护的入口数据、审核和实测 | 资源网站 | 最接近原库，工程和带宽成本较低 |
| 官方播放器嵌入专题站 | 允许嵌入的片目和平台条款适配 | 来源平台 | 可以低成本，但受播放器、收费、广告和可用性规则约束 |
| 获准再分发的垂直视频站 | 逐片许可或供应合同、自有片目表 | 你购买的视频服务 | 当前更适合验证“站内观看”的路线 |
| 丰富商业片库合作 | 渠道准入、可授权片单、分成或授权报价 | 按合同；标准文件交付后通常你安排分发 | Filmhub 是候选，需要商务确认 |
| 直接依赖未知公共接口 | 当前可播的接口 | 可能是上游，具体未知 | 可供本地技术研究，不据此承诺正式产品供应 |

目录信息和免费影片许可可以免费取得；自行保存和分发视频时，基础设施通常另外计费。使用允许嵌入的官方播放器时，也可能由来源平台承担媒体成本，但需要接受相应商业限制。

## 当前建议

先验证“动画短片精选＋原创解析/专题”的需求。以已核实可商业再分发的 Blender 具体作品搭建小片库，再向独立作者、工作室或 Filmhub 申请明确的非独家授权。Bunny Stream 是低用量分发候选，Cloudflare Stream 可按分钟计费对照；两者提供基础设施，不附送影视版权。

Filmhub 的渠道分成真实存在，标准流程向你的存储交付文件。小团队是否获批、你的分成比例、前期费用和最低承诺仍需书面确认。不能把制片人侧的免费计划或 80/20 分配直接当成你建站的价格。[Filmhub 专题](filmhub.md)
