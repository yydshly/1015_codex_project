OUR UNDERSTANDING / 核心判断

从数据入口、业务流程，走向有证据的探索。

01 / 库的定位

招聘业务的工具层

把求职与招聘的读取、整理和动作封装为可描述、可调用的工具。价值在业务适配、结构化合同和本地可恢复流程；基础搜索和规则本身不需要模型。

02 / 访问机制

会话决定条件，通道决定执行环境

主要访问网页内部接口：HTTP 直连、浏览器内 fetch、页面驱动后监听响应各有用途。Cookie、页面令牌、账号权限和服务端检查共同影响访问；未见官方 OpenAPI 授权接入。

03 / 风险与效果

区分能调用、规则命中与真实结果

有效登录态不保证平台放行；内部接口可能变化。消息超时后的远端结果可能未知，apply 不证明简历附件送达。本页演示合成数据，未测真实账号通过率、封禁率或录用效果。

04 / 可扩展价值

用岗位证据形成探索问题

复用搜索、详情、保存和导出，增加技能与任务提取、归一化、去重和采样方法，可做职业画像、方向比较和个人差距表。JD 之外还需从业者访谈、个人经历与实践证据。

阅读时区分三层：源库已有能力、本研究的合成演示、仍需开发和验证的扩展。模型 API 与 BOSS 数据接口也是两条不同的数据流。

02 / MECHANISM

网页接口与浏览器，具体如何配合？

接口决定取什么数据，
浏览器或 HTTP 客户端决定在哪里请求。

核心是复用网页登录态，访问 BOSS 网页内部接口。

普通搜索在浏览器内调用接口取 JSON；详情等请求按会话模式选择通道；专用 crawl 会驱动页面并监听网络响应。所查源码未显示官方开放平台的授权接入，不能把 CLI / MCP 的调用接口当成 BOSS 官方 OpenAPI。

BOUNDARIES / RISKS

有登录态、有浏览器，仍然有风险。

下列为源码机制与使用边界分析；
本轮没有测试真实账号的通过率或封禁率。

01 / 平台风控

访问仍可能被拒绝

账号、IP、频率与会话环境都会影响结果。401、429、安全验证页及平台业务码需分类处理；code 37 也不能脱离上下文一律当成可刷新令牌。

已有控制：节流、预算、冷却与风险锁。遇到风险停止，保留状态并到官方页面核实；这些控制不保证平台放行。
02 / 接口与页面变化

内部接口缺少稳定契约

接口路径、字段、页面令牌或聊天页运行时变化，都可能使适配失效。页面采集还依赖浏览器版本、滚动加载与监听行为。

使用固定版本、小样本核对与明确错误；返回 JSON 成功也需检查业务状态和数据是否完整。
03 / 会话与资料

Cookie、简历和调试端口须保护

会话文件、浏览器用户目录和调试端口具有敏感访问能力；SQLite 与导出文件也可能包含岗位、个人资料和聊天内容。

凭据不进入网页、日志或 Git；限制本机端口与文件访问，只保存完成任务所需的数据。
04 / 真实写操作

超时不等于对方没收到

打招呼、消息和职位状态会产生真实影响。连接异常时远端结果可能未知，重复调用可能重复执行；apply 命令名也不保证完整投递。

源码仅对已标注 replay_safe 的适用请求开放自动重试；写操作需核对结果，按业务要求设置确认与记录。
05 / 模型服务

分析内容可能离开本机

启用 AI 后，输入会发到配置的模型端点。外部服务可能产生费用与资料处理风险；生成建议也可能遗漏事实或编造依据。

检查目的端、输入范围与保留设置；必要时脱敏或使用本地服务，重要结论回查原文。
06 / 分析可信度

命中规则不等于真实职业结论

子串规则会误解否定；搜索结果可能个性化、有重复或样本偏差。JD 描述的是招聘要求，无法独自说明真实工作体验或录用机会。

保留原文、时间与采样条件，去重并人工复核。本页合成样本只说明输出形态，不代表市场统计。
!

平台允许访问与账号已有权限，是实际使用的前提。

自动化访问、保存和再利用数据，应核对平台现行规则与相应授权。开源许可只覆盖库代码的使用；CLI、MCP 或浏览器通道都不会扩大平台数据权限。
