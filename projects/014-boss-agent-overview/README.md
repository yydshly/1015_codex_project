# 014 · BOSS Agent CLI 能力总览与职业探索研究

**boss-agent-cli 把 BOSS 求职与招聘的搜索、筛选、候选池、简历和沟通组织成 CLI / Python API / MCP 工具。** 它复用网页登录态，通过 HTTP、浏览器内 fetch 和页面网络监听访问网页内部接口，再以本地规则、SQLite 状态及可选模型分析组织结果。访问受平台风控、会话环境、接口变化和数据权限约束。

本研究整理这层业务基础的能力、原理、风险与可见产物，演示候选清单、JSON 和职业画像，并说明扩展职业方向比较、个人差距探索所需的数据与验证。源库已有功能、本研究合成原型与未来扩展分别说明；[008 原始实验](../008-boss-agent-cli/README.md) 保留。

## 我们的理解

它提供招聘业务的工具层：对平台请求、角色权限、业务字段、本地状态、错误与后续动作做统一组织，让人或 Agent 可以接续流程。基础搜索和规则筛选不需要模型；需要 JD、简历或沟通分析时才调用另行配置的模型服务。

“API”与“浏览器”分别描述数据入口和执行环境。普通搜索是在浏览器页面内 fetch 接口取得 JSON；专用 crawl 通过页面操作触发请求并监听响应。Cookie 只是会话条件之一，页面令牌、浏览器环境、账号权限与平台校验同样影响访问。所查源码未显示官方开放平台授权接入。

对职业探索的意义，是把岗位要求整理成有原文依据、能逐项核对的技能和任务资料，再形成学习、访谈与实践问题。真实产品还要补采样口径、提取、术语归一化、去重与证据溯源；个人经历和从业者资料用于补充 JD 的局限。

可调用、规则命中和现实结果属于不同证据层级。本页的合成演示说明呈现形态与规则行为；它不证明账号长期可用、岗位待遇真实、简历送达或录用概率提高。

## 能力：已有业务基础

求职者可搜索和筛选职位、保存本地候选池、整理进度，按需使用 AI 简历分析；招聘者可搜索候选人、处理简历和会话、管理职位；开发者可用 CLI、Python API、MCP 和 schema 接入。当前实际平台注册只有 BOSS。

搜索和词表筛选不需要大模型。AI 分析需配置外部或本地模型服务；平台动作依赖账号权限、会话与风控。`apply` 最小实现复用立即沟通端点，不能据命令名判断附件简历已送达。

## 原理：会话访问与业务处理分工

主要访问 BOSS 网页内部接口，所查源码未显示官方开放平台授权接入。API 是数据请求方式，浏览器是请求环境，两者不是互斥选项。

| 操作 | 取数或处理路径 |
| --- | --- |
| 普通搜索、推荐 | CDP / Patchright 在已登录页面内 fetch → 内部网页接口 JSON |
| 详情、职位卡片 | 允许 HTTP 时可走 httpx；browser-only 会话转浏览器。卡片的普通异常可回退，风险停止异常直接抛出 |
| crawl | DrissionPage 导航、滚动加载与网络响应监听 → joblist JSON；普通监听失败可页面内 fetch；详情也页面内 fetch |
| 部分招聘者操作 | 可通过现有聊天页 JS 运行时处理，依赖页面和权限 |
| 离线候选池与规则 | 本地 SQLite / 字符串判断；刷新与补查详情另需访问平台 |
| AI 分析 | 简历 / JD → 配置的模型服务 /chat/completions；与 BOSS 接口分开 |

显式 CDP、非 auto 浏览器来源或已接入 CDP 会话，会进入 browser-only，不是简单把浏览器 Cookie 拷给 httpx。DOM / 页面状态主要辅助导航、加载和风险检查，不能把职位取数主路径概括为逐条爬 DOM 文本。

网页提供六场景路径切换和带源码链接的对照表。完整分析与风险表见 [architecture.md](architecture.md)：平台风控、内部接口变化、会话与资料保护、写操作结果不明、模型数据流与样本偏差。节流、预算、缓存和风险停止能约束访问，不能承诺平台放行。

## 风险与使用边界

| 风险 | 应理解的边界 |
| --- | --- |
| 平台风控与会话异常 | 有效 Cookie、使用浏览器或降低频率均不保证放行；风险码、安全页和预算耗尽时应保存状态并停止 |
| 内部接口与页面变化 | 路径、字段、令牌与页面运行时可能漂移；本地 schema 和健康状态不证明在线接口可用 |
| 会话、资料与权限 | 会话文件、调试端口、SQLite、导出与简历聊天内容需要限权、脱敏和清理；代码 MIT 许可不扩大平台数据权限 |
| 真实写操作 | 超时后的远端结果可能未知，重复调用可重复执行；apply 的最小实现不证明附件简历送达 |
| 模型资料传输与质量 | 配置外部端点时内容可能离开本机，并产生费用；建议需回查原文，分数不当作录用概率 |
| 分析中的样本偏差 | 词表会误判否定和同义表达；个性化、重复及少量 JD 不能代表整个市场或实际工作体验 |

## 呈现效果：三种可操作的输出

| 输出 | 页面行为 | 数据与实现范围 |
| --- | --- | --- |
| 候选岗位清单 | 切城市、开关双福利，查看命中与人工复核提示 | 复用 008 的 8 个合成岗位；词表移植与原始 Python 结果回归 |
| JSON 工具输出 | 与当前清单同步，可复制文本 | 统一信封的简化示意，并非真实 CLI 或平台响应 |
| 职业画像 | 切后端/数据/AI 应用方向，勾选已有技能，查看技能频次、任务与待探索项 | 本研究新增原型；9 个手工结构化合成岗位，浏览器计算 |

画像技能按“每个岗位是否提及”计数，重复技能不重复累计，能回查样本 ID。勾选不做能力认证、职业决策或录用概率计算。真实产品仍需 JD 提取、归一化、去重与证据溯源。

## 可实现目标：从机会筛选到职业探索

1. 求职机会筛选：复用搜索、规则和候选池，补个人条件与人工核对。
2. 职业画像：复用岗位数据入口，补技能/任务提取、归一化与统计。
3. 方向、城市和行业比较：补可比采样口径、职业分类和薪资范围解析。
4. 个人差距探索：复用简历/JD 分析，补经历证据、差距表与探索行动。
5. 需求变化观察：复用增量读取基础，补历史快照、去重与时间对比。
6. 招聘工作助手：复用招聘者接口，补界面、权限、确认和工作记录。

详细“可复用什么/需补什么/不能得出什么”见 [extensions.md](extensions.md)。这些方向并非库已经提供完整的职业分析系统。
